# Lesson 12 - Running the suite in CI

**Workflow file:** `.github/workflows/playwright.yml`

## The workflow

```yaml
- uses: actions/setup-node@v4
  with: { node-version: 20, cache: npm }
- run: npm ci
- run: npx playwright install --with-deps chromium
- run: npx playwright test
- uses: actions/upload-artifact@v4
  if: ${{ !cancelled() }}
  with:
    name: playwright-report
    path: playwright-report/
    retention-days: 14
```

Points worth understanding:

- **`npm ci`, not `npm install`** - installs exactly what the lockfile says.
- **`--with-deps`** installs the Linux system libraries browsers need. Skip it
  and you get cryptic launch failures.
- **Cache the browsers** (`~/.cache/ms-playwright`) to save ~1 minute per run.
- **`if: ${{ !cancelled() }}`** uploads the report even when tests fail - which
  is exactly when you need it.
- The demo app needs no separate step: the `webServer` block in the config
  starts it and shuts it down.

## Config settings that only apply on CI

```ts
forbidOnly: !!process.env.CI,   // a stray test.only fails the build
retries: process.env.CI ? 2 : 0,
workers: process.env.CI ? 1 : undefined,
```

`forbidOnly` has saved more suites than any other setting - without it, one
committed `test.only` silently reduces your pipeline to a single test.

## Pointing the suite at a deployed environment

`baseURL` reads `BASE_URL`, so:

```bash
BASE_URL=https://staging.example.com npx playwright test
```

For that to be useful, delete the `webServer` block (or guard it) so CI does not
start a local app it will not use.

## Sharding a large suite

```bash
npx playwright test --shard=1/4    # on runner 1
npx playwright test --shard=2/4    # on runner 2, ...
```

Use `reporter: [['blob']]` on each shard and `npx playwright merge-reports` to
produce a single HTML report.

## Docker

```bash
docker run --rm -v $(pwd):/work -w /work \
  mcr.microsoft.com/playwright:v1.62.1-noble \
  npx playwright test
```

Match the image tag to the Playwright version in `package.json`. Running in the
same image locally and in CI is what makes screenshot baselines reproducible.
